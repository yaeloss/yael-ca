Personal website for Yaël Ossowski found on [yael.ca](https://yael.ca).

## Build and verify

Use Hugo **0.166.0 extended** (also pinned in the GitHub Pages workflow) and Python 3:

```sh
hugo --minify
python3 scripts/generate_redirects.py public
python3 scripts/check_seo.py public
python3 scripts/check_performance.py public
python3 scripts/check_media_archives.py public
```

Use a fresh output directory for release builds so deleted archives do not linger. GitHub Actions checks out a fresh workspace on each run. Local preview via `hugo server` includes the 404 fallback; static redirect pages are generated by the post-build Python step.

## SEO metadata

Author identity and external profile URLs live in `params.author` in `hugo.toml`. The homepage, About page, and articles share the stable `https://yael.ca/#person` identity. Post descriptions use front matter, then the summary, then the site description.

Social cards and Article JSON-LD share one image resolver: `image`, `featured_image`, or migrated `coverImage`. Bundle resources resolve relative to the article; static uploads resolve relative to the site. Posts without a usable declared image use the site card. Dimensions are emitted only when known.

## Taxonomies

Ordinary tag and category pages remain available for browsing, but the Hugo cascade excludes them from the sitemap. Curated hubs in `content/tags/` opt back in with `sitemap.disable: false` and include an introduction. To add another hub, create its `_index.md`, add meaningful editorial content, set `topicHub: true` to link it from articles with that tag, and update the hub expectations in `scripts/check_seo.py`.

### Interviews, talks, and video

- Use `categories: ["interviews"]` for TV, radio, podcast, and YouTube interviews, including conversations hosted by Yaël.
- Use `categories: ["talks-panels"]` for presentations, conference panels, moderated event discussions, and public testimony. The displayed title is **Talks & Panels**.
- Add `formats: ["video"]` when a post includes or links to a video recording. This is independent of its category; audio-only interviews do not need a format. The CMS has an optional Formats selector.
- Standalone videos such as travel clips or explainers can have the video format without being labeled interviews or talks. Other existing categories and topic tags are retained.
- `/categories/interviews/` and `/categories/talks-panels/` have introductions and are included in the sitemap as curated hubs. `/formats/video/` is a browsing filter and remains excluded. Navigation on the Posts and Categories archives links to all three.
- `data/archive_moves.json` preserves the former `video`, `videos`, `radio-interviews`, and `testimony` category URLs, including WordPress singular-category URLs and pagination. The old video categories lead to the complete Video format archive. Individual post URLs do not change.

The initial migration classified the old video categories by their article text and added the video format to existing interviews with YouTube/Vimeo recording links. It did not infer that every article linking to a video is an interview, or generate summaries/transcripts from unseen recordings. When adding an interview, include the outlet, date, subjects discussed, and an accurate summary or transcript where available.

`data/tag_merges.json` records five duplicate tag slugs consolidated in article front matter. Keep these mappings so old tag URLs continue to resolve. Single-article tags are retained.

## WordPress URL migration

Hugo produces `legacy-redirects.json` using the URLs and taxonomy counts of published pages. The post-build step generates immediate HTML refresh pages with canonical links for root-level post slugs, dated post URLs, singular `/tag/` and `/category/` archives, merged tags, and archive pagination. Pagination uses WordPress's default of 10 posts per page; the 404 fallback covers other page numbers when a matching archive exists. Unknown slugs stay on the searchable 404 page.

**Hosting limitation:** GitHub Pages serves these as HTML redirects, not HTTP 301 responses. `redirects.csv` exports the exact mappings with the intended 301 status for a future proxy or host with redirect support; GitHub Pages does not consume this CSV. Server redirects, WordPress numeric `?p=ID` URLs, and historic renamed slugs require hosting configuration or an original URL export. Do not redirect unmatched URLs to unrelated content.

The generated `robots.txt` declares the sitemap. Sitemap exclusion alone does not remove existing search results, and structured data does not guarantee name-search rankings.

## Search and AI discovery

Articles include a visible byline linking to the canonical biography. Their text, dates, author links, and topic navigation are rendered in HTML, so discovery does not depend on executing the site's JavaScript search. The wildcard robots policy allows search and AI crawlers; the SEO check verifies access to sitemap URLs for Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User, PerplexityBot, and Claude-SearchBot. This tests the generated policy, not any restrictions imposed by the live host or proxy.

After deployment, submit the sitemap in Google Search Console and Bing Webmaster Tools, inspect the homepage, biography, and topic hubs, and check live crawler access. Track branded search impressions/clicks and AI citation trends. Bing's [AI Performance report](https://www.bing.com/webmasters/help/ai-performance-9f8e7d6c) reports citations in supported Microsoft AI experiences.

Google's [AI search guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) emphasizes useful content and normal SEO foundations and states that `llms.txt` does not affect Google Search visibility. Allowing crawling makes pages available for discovery; it does not guarantee citations or change an LLM's already-trained knowledge.

## Performance and merge notes

Merge the project changes in `layouts/`, `assets/`, `content/`, `data/`, `static/`, `scripts/`, `.github/workflows/`, `hugo.toml`, `.gitignore`, `IMAGE-SOURCES.md`, and this README. The theme is unchanged. Do not commit `public/`, `resources/`, temporary preview builds, or Python caches.

- Search downloads its index and pinned, locally hosted Fuse library on focus or submission, rather than on page load. Search code is deferred, fingerprinted, and included only on the homepage and 404 page; articles get a small back-to-results script. Failed loads offer a retry and the article archive.
- Lora variable fonts are self-hosted with `font-display: swap`; the normal Latin font is preloaded. Font and search-library licenses are included. Latin and extended Latin are bundled, with system serif fallbacks for other scripts.
- Markdown images and CMS cover images receive responsive WebP versions at up to 480, 800, and 1400 pixels, without upscaling. Dimensions reserve layout space. Leading images load eagerly; subsequent images and embedded players load lazily. Originals remain available. Remote images and animated GIFs pass through.
- CMS uploads stay in `static/images/uploads/`; Hugo mounts them as assets for processing. GitHub Actions caches processed images and checks the generated SEO and performance output before deployment.
- Local comparison: 464 responsive images used about 80.5% fewer bytes in their largest generated versions than their previous image sources (138.4 MB to 26.9 MB in aggregate). The search index decreased from 3.16 MB to 2.26 MB uncompressed. These are asset-size measurements, not live Core Web Vitals scores.

Seven broken article images have been replaced: six public-domain/CC0 images and a recreated historical pay chart. See [IMAGE-SOURCES.md](IMAGE-SOURCES.md) for sources, rights, and reproduction notes. Two unidentifiable graphics in the Effective Altruism article are no longer embedded; their invalid source files remain for possible recovery. Five additional embeds pointing to absent files in the repaired articles were also removed and documented. After deployment, check real-device performance and crawler access on the live domain.
